# Release readiness checklist

## Functionality
- [ ] Main user journeys have been exercised from start to finish.
- [ ] Empty, invalid, and boundary inputs have been tested.
- [ ] Known limitations are documented.

## Quality
- [ ] Automated tests pass in a clean environment.
- [ ] No debug credentials, tokens, or personal data are committed.
- [ ] Error messages are useful and do not expose internal details.
- [ ] Dependencies and runtime versions are documented.

## Delivery
- [ ] Setup and run instructions are current.
- [ ] Database or data migration steps are documented where applicable.
- [ ] A rollback or recovery approach is understood.
- [ ] Release notes summarize user-visible changes.

A checklist item should be marked complete only after it has been verified. Record exceptions rather than silently skipping them.
